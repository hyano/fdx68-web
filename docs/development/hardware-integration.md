# 実機統合テスト手順

Raspberry Pi + FDX68 + X68000 実機を使う、手動のチェックリストです。

**自動化できないだけでなく、順序を間違えると実機やディスクイメージを壊す可能性があります。**
前提条件を確認しながら順に進めてください。

---

## 実行前の確認

- [ ] ディスクイメージのバックアップを取ってある（テストで消える可能性を許容できる状態）
- [ ] X68000 の電源が入っていない（Step 1 の時点では OFF）
- [ ] Raspberry Pi に FDX68 専用シールドが正しく装着されている
- [ ] `./scripts/test.sh` が macOS 上で全て通っている

---

## Step 1: X68000 の電源を切った状態での確認

**最初のテストは必ず X68000 の電源を切った状態で行ってください。**
実機がディスクにアクセスしている最中にエミュレータを起動・停止しないためです。

### サービスの起動

- [ ] `./scripts/deploy.sh` が成功する
- [ ] `curl http://<Pi>:8000/api/health` が 200 を返す
- [ ] ブラウザで Web UI が開く

### fddemu の起動・停止

- [ ] Web UI の `[Start]` で fddemu が起動する
- [ ] Pi 上で `pgrep -a fddemu` にプロセスが見える
- [ ] Web UI の表示が「Running」になる
- [ ] `[Stop]` で停止する。`pgrep -a fddemu` で消えている
- [ ] 停止後、Web UI の表示が「Stopped」になる（エラーにならない）

### 確認済みの挙動の再確認

- [ ] `fddctl --stop` で停止し、`pgrep -x fddemu` で消えている
      （`journalctl` に pkill へフォールバックした記録が**出ていない**こと）
- [ ] 停止後に残留プロセスやソケットファイルが残らない
- [ ] **ライトプロテクトを ON にした直後、もう一度 ON にしても状態が変わらない**
      （`-c protect` はトグルなので、状態を確認せず実行すると逆になる）

### ドライブ操作

- [ ] Drive 0 にイメージを挿入できる
- [ ] `fddctl -l` の実出力と Web UI の表示が一致する
- [ ] Drive 1 にも挿入できる
- [ ] イジェクトできる
- [ ] ライトプロテクトを切り替えられる。`fddctl -l` の `WP` 欄が変化する

---

## Step 2: ファイル操作の確認（X68000 は電源 OFF のまま）

### 日本語ファイル名

X68000 のソフトはディレクトリ名を日本語で管理することが多いため、重点的に確認します。

- [ ] 日本語名のフォルダを作成できる
- [ ] その中に日本語名のイメージを置ける
- [ ] 日本語名の FDX を Drive 0 に挿入できる
- [ ] **`fddctl -l` の実出力と Web UI の表示が文字化けせず一致する**

> **必ず systemd 経由で起動したサービスで確認してください。**
> 対話 SSH とはロケールが異なるため、SSH で手打ちして問題なくても
> サービスでは化ける、という食い違いが起こりえます。

### アップロード・ダウンロード

- [ ] macOS のブラウザから数 MB の FDX をドラッグ＆ドロップできる。進捗が表示される
- [ ] 大きめの RAW 形式 FDX（数十 MB）もアップロードできる
- [ ] **転送中に Pi 側で `free -m` を見て、メモリ使用量が跳ね上がらないこと**
      （ストリーミング書き込みができている確認）
- [ ] 転送を途中で中断し、**`.part` ファイルが残らないこと**
- [ ] アップロードしたイメージを Drive 0 に挿入して実機から読める
      （ファイルが破損していないことの最終確認）
- [ ] 「FDX に自動変換」をオンにして D88 / XDF をアップロードすると、元ファイルと FDX が並び、
      FDX を挿入して実機から読める
- [ ] 同名の FDX がある状態で自動変換付きアップロードをすると、警告が出て既存の FDX が変わらない
- [ ] 日本語名のイメージをダウンロードし、macOS 側に正しい名前で保存される

### 移動・複製

- [ ] ツリー内でイメージを別フォルダへドラッグして移動できる
- [ ] Option 併用でコピーになる
- [ ] **フォルダを自分自身の子孫へドロップしようとしても拒否される**
- [ ] 挿入中のイメージの移動が拒否される
- [ ] 複製した FDX を `fdxview` で開き、元と同じトラック構成である

### 変換

- [ ] 実際の `.d88` または `.xdf` を Web UI から変換して `.fdx` が生成される
- [ ] `fdxview` でトラック情報が読める
      （拡張子変更ではなく実変換が行われていることの確認）
- [ ] 変換先が既に存在する場合、上書きされずエラーになる
- [ ] 元ファイルが変更されていない

### 新規イメージ作成

- [ ] Web UI から 2HD のブランクイメージを作成できる
- [ ] Pi 上で `fdxtool <作成した FDX>` を実行し、種別 2HD・360rpm・
      指定したディスク名が反映されている

### 一括操作

- [ ] 10 件を選択して一括削除する。うち 1 件を挿入中にしておく
- [ ] **その 1 件だけがスキップされ理由が表示され、残り 9 件は削除される**

### 外部変更への追随

- [ ] ブラウザでツリーを開いたまま、SSH で Pi 側にファイルを置く／消す
- [ ] `[⟳ 更新]` で反映される
- [ ] 別タブに移動して戻るだけでも反映される
- [ ] 展開状態とスクロール位置が保たれる
- [ ] ブラウザを 2 つ開き、一方でアップロードや削除を行うともう一方も自動更新される
- [ ] SSH で消したファイルに Web UI から挿入を試みると、
      分かりやすいエラーが出たうえで一覧が実態に合わせて更新される
- [ ] SSH から `fddctl -i 0 -c insert` で挿入すると、
      Web UI のドライブ表示が 2 秒以内に追随する

---

## Step 3: X68000 実機を接続しての確認

**ここから実機の電源を入れます。**

### 起動ディスク

- [ ] Drive 0 に X68000 の起動ディスクの FDX を挿入する
- [ ] X68000 の電源を入れ、そのディスクから起動できる
- [ ] ディスクアクセス中に Web UI のシリンダ表示（CL）が変化する

### ディスク交換

- [ ] 複数枚組ソフトを起動し、ディスク交換要求が出たら Web UI から Drive 0 のイメージを交換する
- [ ] X68000 が新しいディスクを認識する
- [ ] 交換のタイミングが実用上間に合う

### ライトプロテクト

- [ ] Web UI でライトプロテクトを ON にすると、X68000 側から書き込めなくなる
- [ ] OFF にすると書き込める

### ブランクディスクのフォーマット

- [ ] Web UI で作成したブランク 2HD を Drive 1 に挿入する
- [ ] X68000 の `FORMAT.X` でフォーマットできる
      （作成したイメージが実機から書き込み可能な実体であることの確認）
- [ ] フォーマット後、そのディスクにファイルを保存できる
- [ ] 保存したイメージを Web UI からダウンロードし、`fdxview` で内容を確認できる

### アクセス中の操作（注意して実施）

- [ ] ディスクアクセス中に Web UI が「アクセス中の可能性があります」と警告を出す
- [ ] アップロード中でも X68000 のディスクアクセスが破綻しない
      （SD カードへの書き込みが fddemu のリアルタイム動作に影響しないか）

---

## Step 4: システム操作（最後に実施）

**これらは実行するとテストが中断されるため、他の項目をすべて終えてから行ってください。**

- [ ] X68000 の電源を切る
- [ ] Web UI から再起動する。確認ダイアログが表示される
- [ ] 再起動後、`fdx68-web` サービスが自動起動している
- [ ] **`fddemu` は自動起動していない**（意図的にそうしている）
- [ ] Web UI からシャットダウンする。確認ダイアログが表示される
- [ ] Pi が正常に停止する

---

## 結果の記録

未確定事項の確認結果は [fdx68-version-notes.md](../reference/fdx68-version-notes.md) に追記してください。
挙動が公式ドキュメントと異なっていた場合は、その差異も記録します。

問題が見つかった場合は、再現手順とともに Issue に記録してください。
その際、以下の情報を含めてください。

- Raspberry Pi のモデルと OS のバージョン
- FDX68 のバージョン
- `fddctl -l` の実際の出力
- `journalctl -u fdx68-web` の該当部分
