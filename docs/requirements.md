# 要件

## 背景と目的

X68000 実機の FDD インターフェースには FDX68 が接続されており、
Raspberry Pi 上の `fddemu` がフロッピーディスクドライブをエミュレーションしています。

これまでディスクイメージの挿入・交換は、Raspberry Pi に SSH でログインして
`fddctl` を手打ちする必要がありました。X68000 の前に座ってソフトを動かしている最中に
別の端末を操作するのは煩雑で、特に**複数枚組ソフトのディスク交換**では実用上の障害になります。

本システムは、この操作を Web ブラウザから完結させることを目的とします。

```
ユーザー操作（ブラウザ）
    ↓
ディスクイメージ
    ↓
FDX68 / fddemu
    ↓
FDD 信号
    ↓
X68000 実機
```

## 機能要件

### FDD エミュレーション制御

| 要件 | 内容 |
|---|---|
| fddemu の状態確認 | 起動しているかどうかを表示する |
| fddemu の起動 | バックグラウンドで起動し、起動後に疎通確認する |
| fddemu の停止 | `fddctl --stop` を試み、残った場合は `pkill -x` で停止する |
| ディスク挿入 | Drive 0 / Drive 1 にイメージを挿入する |
| ディスク排出 | Drive 0 / Drive 1 のイメージを排出する |
| ライトプロテクト | 実行時のライトプロテクトを切り替える |

### 状態監視

`fddctl -l` を一定間隔（既定 2 秒、`FDX68_STATUS_INTERVAL` で変更可）で実行し、
以下を Web UI に表示します。

- fddemu の稼働状態
- Drive ID
- ライトプロテクト状態
- シリンダ位置
- 挿入中のディスクイメージのパス（未挿入なら EMPTY）

状態が変化したときのみ WebSocket でクライアントに通知します。

### ディスクイメージ管理

| 要件 | 内容 |
|---|---|
| 一覧表示 | Finder のようなツリー形式。展開時に遅延読み込み |
| アップロード | ドラッグ＆ドロップ。投入先はドロップしたフォルダ |
| ダウンロード | Pi 上のイメージを手元 PC に保存 |
| 移動 | ツリー内のドラッグ＆ドロップ（Option 併用でコピー） |
| 複製 | 同一ディレクトリに連番付きの名前で複製 |
| リネーム | ファイル・フォルダ共通 |
| 削除 | 確認ダイアログ必須。空でないディレクトリは削除不可 |
| 新規フォルダ作成 | |
| 新規イメージ作成 | `fdxtool -c` によるブランク FDX の生成（2D / 2DD / 2HD） |
| FDX 変換 | `fdxconv` による非 FDX → FDX の変換 |
| FDX 情報表示 | `fdxtool` によるディスク情報の表示 |
| ディスク属性編集 | `fdxtool -s` によるディスク名・WP 属性の変更 |
| 複数選択・一括操作 | 移動・削除・変換をまとめて実行 |

対象とするファイル種別:

- `directory`
- `fdx` … `.fdx`（大文字小文字を区別しない）
- `convertible_image` … `.xdf .2hd .hdm .img .dup .2hc .2hq .2dd .dim .d88 .d68 .d77 .fdi .fdd .nfd`
- `unsupported` … それ以外

### システム操作

- Raspberry Pi の再起動
- Raspberry Pi のシャットダウン

いずれも確認ダイアログを必須とします。

## 非機能要件

### 安全性（ディスクイメージの保護）

ディスクイメージは代替不能な資産であるため、以下を厳守します。

- 変換時に元ファイルを変更しない
- 既存ファイルを無断で上書きしない（変換・アップロード・複製・移動・新規作成のすべて）
- 挿入中のイメージを削除・リネーム・移動しない
- 書き込みは `.part` 経由の原子的置換とし、中途半端なファイルを残さない
- 拡張子の変更を「変換」として扱わない

### 安全性（実機の保護）

- fddemu の停止、Pi の再起動・シャットダウンは確認を必須とする
- X68000 がアクセス中の可能性がある操作には注意表示を出す
  （シリンダ位置の変化を「直近にアクセスがあった」ヒントとして使う）

### セキュリティ

- クライアントから絶対パスを受け取らない
- すべてのパスをイメージルート配下に制限する（`Path.resolve()` による検証）
- `subprocess` は引数リスト形式で呼び、`shell=True` を使わない
- アップロードのファイル名はベース名に切り詰め、拡張子を制限する

認証機能は実装しません（LAN 内限定運用が前提）。
ただし将来の追加に備え、認証は 1 つの FastAPI 依存関数に集約できる構造にします。

### 性能・資源

実行環境は Raspberry Pi 3 Model A+（実装メモリ 415MB / 空き 275MB）です。

- アップロード・ダウンロード・複製はストリーミングで処理し、メモリに全体を載せない
- フロントエンドにビルド工程を持たない（Pi に Node 環境を置かない）
- ツリー全体の定期スキャンを行わない（SD カードへの負荷が fddemu に影響するため）
- uvicorn はワーカー 1、本番では `--reload` なし

### 保守性

- FastAPI から直接 subprocess を呼ばず、Service Layer / Backend / CommandRunner に分離する
- バックエンドの切り替えはファクトリで一元化し、OS 判定をコード中に散在させない
- macOS では Mock バックエンドで開発・テストできる

## 将来の検討事項

現時点では実装しないが、有用性が見込まれるもの。

| 項目 | 見送った理由 |
|---|---|
| 名前での絞り込み検索 | イメージが数百個規模になったら再検討 |
| フォルダの ZIP 一括ダウンロード | Pi 3A+ の CPU に対して圧縮処理が重い |
| FDX → 他形式への逆変換 | 形式ごとの制約が多く、失敗パターンの説明が難しい |
| `fddump` / `fdrestore` による実 FDD のダンプ・書き戻し | FDX68 のコントローラモードを使う大きな機能で、実 FDD の接続が前提 |
| 認証機能 | LAN 内限定運用が前提のため。公開する利用者が増えたら再検討 |
| お気に入り / 最近使ったイメージ | 起動ディスクの素早い挿入に有用だが、まず基本機能を優先 |
